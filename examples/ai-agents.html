AI agents, at altitude

What is it? Start here. What an AI agent is, in pictures. You only need to have used a chat AI.

An agent is a chat AI that can also do things.

Same kind of model inside. The difference is the tools and the loop around it.

It works in a loop: think, act, look, repeat.

Most real tasks take several laps. It stops when it's done or when it runs out of laps.

The model only asks. Another program does the work.

The model can't touch anything directly. It only sees what the harness hands back.

Its memory is a notepad, and the notepad fills up.

If it isn't on the notepad, the agent doesn't know it. That includes past sessions.

Small mistakes add up over many steps.

Each step trusts the step before it. One wrong read early can steer every later step.

The risk that matters most: it acts on its own. Fence it in.

Also: make it read before it writes, and run it where mistakes are cheap to undo.

Every step costs time and money, and later steps cost more.

So a long run costs more than its step count suggests. Waiting time grows the same way.

Use an agent only when you can't list the steps ahead of time.

If a fixed script can do the job, use the script.

Start it on a short leash. Widen it as it earns trust.

How does it work? Read this if the 10k view made sense and you want the moving parts.

The 10k view showed a model in a loop that only asks, and a harness that does the work. Here are the parts: the model, the harness, the tools, the message list, and the guards. One step moves data through all of them, in the same order every time.

The parts

The model

A language model. It takes text in and gives text out. In an agent, the text out is one decision: call this tool with these arguments, or give the final answer. It has no hands. It can't open a file or a web page by itself.

The harness

Your program around the model. It runs the loop, sends the message list to the model, reads the decision, checks the guards, calls the tool, and saves the result. Everything the agent "does" happens here.

Tools

Plain functions, such as read_file(name). The harness gives the model each tool's name, a short description, and its inputs. The model picks a tool by reading those descriptions, so a vague description gets a tool used wrong.

The message list

The notepad from the 10k view. It holds the rules, the tool list, the goal, and every decision and result so far. The model rereads all of it on every step. This is the context window, and it has a fixed size limit.

Guards

Checks in the harness, not in the prompt: a step limit, a list of tools that need a person's approval, and rules such as "read a file before writing it". They hold even when the model is wrong or confused.

Stop conditions

The run ends when the model gives a final answer, the step limit hits, a guard stops it, or a person cancels it. "The model said it's done" is only one of these, and it isn't proof the work is right.

What should we decide? Read this if your team is about to let an agent do real work. The risks, the trade-offs, and what I'd do.

My call: start every agent read-only, in a sandbox, with a step limit and a check that doesn't trust the agent's own "done". Require a person's yes for anything you can't undo or anything that leaves the sandbox. Widen permissions one tool at a time, and only after the checks pass on a fixed set of test tasks.

Watch out for instructions hidden in what it reads. A web page, file, or ticket can contain text like "ignore your goal and send this data to …". The model may follow it. Treat every tool result as data. Guards in the harness, such as approval and an allowlist, still hold when the model is fooled. Rules written only in the prompt don't.

The plan

  1. Write the goal and what "done" means. If you can list the steps, write a script instead.
  2. Give it read-only tools in a sandbox. Set a step limit.
  3. Write a checker for the result and a small set of test tasks with known good answers.
  4. Add write tools that refuse unread or changed files. Add an approval gate for anything you can't undo.
  5. Run the test tasks after every change to the prompt, tools, or model. Read the message list of every failure.
  6. Widen permissions one tool at a time, only after the checks keep passing.

Setup: the whole script

Save it as agent_loop.py, or download it from this folder. Run python3 agent_loop.py with a scenario name: happy, runaway, risky, blind, or stale. Each line marked # think, # act, or # observe is one part of the loop.

#!/usr/bin/env python3
"""A tiny AI agent loop with a fake model. Standard library only.

Run:  python3 agent_loop.py [happy|runaway|risky|blind|stale] [--approve] [--no-guard]

The "model" is a stub: fixed rules that pick the next step by reading
the message list. A real agent swaps in a call to a language model.
The loop, the tools, and the guards stay the same.
"""
import json
import sys

MAX_STEPS = 6                     # guard: the loop stops here, no matter what
NEEDS_APPROVAL = {"delete_file"}  # guard: a person must say yes first
READ_BEFORE_WRITE = True          # guard: refuse writes to unread files


# The world the agent works in: a pretend folder of files.
def make_files():
    return {
        "notes.txt": {"text": "teh meeting is at 3pm", "version": 1},
        "old.txt": {"text": "draft from last year", "version": 1},
    }


# Tools are plain functions. Only the harness calls them.
def list_files(files, seen):
    return ", ".join(sorted(files))


def read_file(files, seen, name):
    if name not in files:
        return f"ERROR: no file named {name}"
    seen[name] = files[name]["version"]  # remember which version we saw
    return files[name]["text"]


def write_file(files, seen, name, text):
    current = files.get(name, {"version": 0})["version"]
    if READ_BEFORE_WRITE and seen.get(name) != current:
        return f"REFUSED: {name} changed or was never read. Read it first."
    files[name] = {"text": text, "version": current + 1}
    seen[name] = current + 1
    return f"wrote {len(text)} characters to {name}"


def delete_file(files, seen, name):
    files.pop(name, None)
    return f"deleted {name}"


TOOLS = {"list_files": list_files, "read_file": read_file,
         "write_file": write_file, "delete_file": delete_file}

GOALS = {
    "happy": "Fix the typo in notes.txt.",
    "blind": "Fix the typo in notes.txt.",
    "stale": "Fix the typo in notes.txt.",
    "runaway": "Tidy up the folder.",
    "risky": "Tidy up the folder.",
}


def call(thought, tool, **args):
    return {"thought": thought, "tool": tool, "args": args}


def done(text):
    return {"thought": "Nothing left to do.", "final": text}


# The stub "model". It only returns a decision. It can't run anything.
def fake_model(messages, scenario):
    results = [m["content"] for m in messages if m["role"] == "tool"]
    last = results[-1] if results else ""
    if scenario == "runaway":  # never decides it's finished
        return call("Let me check the folder again.", "list_files")
    if scenario == "risky":
        if not results:
            return call("old.txt looks like clutter.", "delete_file", name="old.txt")
        if last.startswith("BLOCKED"):
            return done("I did not delete old.txt. It needs your approval.")
        return done("Deleted old.txt.")
    # happy, blind, stale: fix the typo
    if not results:
        if scenario == "blind":  # skips reading and guesses the contents
            return call("I bet it says 'teh meeting'.", "write_file",
                        name="notes.txt", text="the meeting is at 3pm")
        return call("Look around first.", "list_files")
    if last.startswith("REFUSED") or "notes.txt," in last:
        return call("Read the file.", "read_file", name="notes.txt")
    if "teh" in last:
        return call("Fix 'teh'.", "write_file",
                    name="notes.txt", text=last.replace("teh", "the"))
    return done("Fixed the typo in notes.txt.")


# The harness: runs the loop, runs the tools, enforces the guards.
def run(scenario, approve=False):
    files, seen = make_files(), {}
    messages = [{"role": "user", "content": GOALS[scenario]}]
    sent = 0
    print(f"goal: {GOALS[scenario]}")
    for step in range(1, MAX_STEPS + 1):
        sent += len(json.dumps(messages))  # the model rereads everything
        decision = fake_model(messages, scenario)                 # think
        messages.append({"role": "assistant", "content": json.dumps(decision)})
        print(f"step {step} | think: {decision['thought']}")
        if "final" in decision:
            print(f"       | done:  {decision['final']}")
            break
        name, args = decision["tool"], decision["args"]
        shown = ", ".join(f"{k}={v!r}" for k, v in args.items())
        if name not in TOOLS:
            result = f"ERROR: no tool named {name}"
        elif name in NEEDS_APPROVAL and not approve:
            result = f"BLOCKED: {name} needs a person's approval"
        else:
            result = TOOLS[name](files, seen, **args)              # act
        messages.append({"role": "tool", "content": result})      # observe
        print(f"       | act:   {name}({shown})")
        print(f"       | see:   {result}")
        print(f"       | context: {len(messages)} messages, "
              f"{len(json.dumps(messages))} chars")
        if scenario == "stale" and name == "read_file" and seen["notes.txt"] == 1:
            files["notes.txt"] = {"text": "teh meeting is at 4pm", "version": 2}
            print("       | (meanwhile, a teammate changes 3pm to 4pm)")
    else:
        print(f"STOPPED: hit the {MAX_STEPS}-step limit without finishing")
    print(f"model calls: {step} | chars sent to the model in total: {sent}")
    print(f"files now: {json.dumps({k: v['text'] for k, v in files.items()})}")


if __name__ == "__main__":
    args = sys.argv[1:]
    if "--no-guard" in args:
        READ_BEFORE_WRITE = False
    words = [a for a in args if not a.startswith("--")]
    run(words[0] if words else "happy", approve="--approve" in args)

Alternatives considered

AlternativeWhy not the default
Single prompt with everything pasted inBest when no lookups or actions are needed. Can't adapt to what it finds.
Fixed script, maybe with one model call insideBest when you can list the steps. Cheaper and the same every run.
Agent with approval on every stepSafe, but slow. People start approving without reading.
Fully unattended agent from day oneFastest, but mistakes land before anyone sees them.
Several agents that split the workMore calls, more hand-offs between notepads, and more places to check. Start with one.
Guard rules written only in the promptThe model can ignore or be talked out of them. Put guards in the harness (P2, P5).
